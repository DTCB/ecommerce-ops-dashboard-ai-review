# 面试讲解稿

## 3 分钟版本

这个项目是一个电商运营数据分析看板和 AI 复盘助手，主要面向数据分析和运营数据分析场景。我使用 Olist 公开电商数据，把订单、商品、用户、支付、评价等多张原始 CSV 清洗建模成订单宽表、商品明细宽表和用户宽表。

在指标层，我没有只做简单图表，而是围绕经营诊断设计了 GMV、订单量、客单价、复购率、取消率、cohort 留存、品类贡献和履约体验指标。因为 Olist 没有曝光和访问数据，所以我没有虚构转化率，而是用履约率、取消率、复购和评分来解释经营质量。

看板分为总览、经营诊断、品类商品、用户地域、履约体验和 AI 复盘几个页面。经营诊断页会识别 GMV 异常波动和环比下滑品类，AI 复盘页会把 KPI、异常、品类变化和履约数据整理成结构化上下文，调用 OpenAI 兼容接口生成日报/周报/月报；如果没有 API Key，会自动降级为模板复盘，保证演示稳定。

这个项目让我完整走了一遍数据清洗、指标体系、可视化诊断、异常识别和业务复盘的链路，也能体现我对数据分析和运营场景的理解。

## 8 分钟版本

我做这个项目的目标不是做一个普通 Streamlit Demo，而是模拟运营数据分析实习中常见的经营复盘场景。业务问题是：如果运营同学看到 GMV 波动，应该如何快速判断是品类结构、用户复购、地域、履约体验还是订单状态造成的。

数据层我使用 Olist Brazilian E-Commerce Public Dataset。原始数据包括订单、订单商品、支付、评价、用户、商品、卖家和品类翻译。我先把这些表清洗成三层模型：订单宽表负责订单状态、购买时间、支付、评价、用户地域和履约时长；商品明细宽表负责品类、卖家、价格和运费；用户宽表负责首购、复购、累计 GMV 和订单数。

指标层我重点做了可解释口径。GMV 默认只统计已交付订单，并支持商品金额和含运费两种口径。订单量、客单价、复购率、cohort 留存、取消率、履约率和评分都和业务问题对应。这里我特别注意没有做虚假的访问转化率，因为 Olist 没有访问曝光数据，强行做会影响项目可信度。

看板层分六个页面。总览页看核心 KPI 和趋势；经营诊断页用滚动均值和 z-score 找 GMV 异常，用最近两个月对比找下滑品类；品类页看品类贡献和价格带；用户地域页看复购和 cohort；履约体验页看交付时长、延迟和评分；AI 复盘页把结构化指标摘要送给 LLM 生成复盘建议。

AI 部分我做了双模式。真实 API 使用 OpenAI 兼容接口，通过环境变量配置 Key、Base URL 和模型，因此可以接 OpenAI、DeepSeek 或通义等服务。为了保证面试演示稳定，如果没有配置 API 或接口失败，系统会自动使用模板复盘。模板不是固定废话，而是会读取当前筛选后的 KPI、异常和品类变化。

如果继续优化，我会加入地理地图、评论文本主题分析、Excel 导出和复盘归档，也可以把 Streamlit 升级成 FastAPI + React。但第一版我优先保证数据分析链路完整、业务口径可信、面试能讲清楚。
